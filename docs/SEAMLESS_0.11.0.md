# 0.11.0 连续切集实现与验证

本版在现有共享缓存预加载之上增加单播放器连续队列。开启“预加载”和“自动连播”后，完整缓存且解析校验通过的下一集会提前加入同一个 ExoPlayer，并预备约 3 秒媒体样本。自然切集不再 stop / clear / prepare，也不重建视频 Surface。预加载仍默认关闭，原有时间/集数设置继续生效。

## 实现边界

- 播放器只保留当前集和紧邻下一集；更远的剧集仍由原来的磁盘窗口负责。
- 候选必须完整缓存，加入队列后强制只读本地缓存；文件缺失或截断不会暗中改走网络。尚未完整准备的下一集沿用 0.10.0 的部分缓存接管和前台准备。
- 队列持有的缓存继续计入容量、元数据、时间/集数预算，并排除重复下载。资源等待 MediaSource 和 MediaPeriod 真正释放后关闭，退出播放器清理残余项。
- 集数、标题、清晰度、进度和重试预算随真实媒体项转换更新。旧集完成记录使用旧位置快照，避免把新集位置写进上一集。
- 播完定时、自动连播关闭、手动跳集、重播和关闭预加载分别处理；手动跳集不扣除“再播完 N 集”的计数。
- 下一集预备失败清除候选；当前集播放错误仍走原有有界恢复。保留应用名称、包名、签名、眼镜输入法、双指菜单和双目显示路径。

## 本地 Android 验证方法

独立 API30 Android 模拟器，正式应用内的 Media3 1.8.0、RemoteVideo、VideoDataSource、SeamlessPlaybackQueue 和实际 Android HEVC 解码器。没有新增供用户安装的测试应用。基线为结束后替换源并 prepare，新方案为连续队列，两组都读取完整本地缓存以排除网络变量。

帧间隙使用 VideoFrameMetadataListener 的 releaseTimeNs，属于解码器计划呈现时间，不是物理面板测量。模拟器使用软件 HEVC 解码器和虚拟 AudioTrack。正式对照保持正常音频 backend 并将播放器音量设为零；欠载计数不能替代实际听感。两组都只初始化一个视频解码器，收益不能描述成减少解码器初始化次数。

本地原始证据位于 `outputs/seamless-android-lab`，不将视频素材、接口身份或内容密钥提交到仓库。

### 正式同环境 A/B：每组 21 项、20 次边界

两组在同一正常音频 backend、默认同步 MediaCodec、默认 250ms PCM 缓冲、静音输出下运行，同样使用完整缓存的三秒 HEVC/AAC 衍生素材。旧流程帧间隙中位数 113.85ms，样本 P95 136.49ms，最大 156.59ms；连续队列中位数 33.33ms，样本 P95 33.37ms，最大 50.00ms。30fps 的自然帧间隔约 33.33ms，因此多数边界已接近正常相邻帧。

两组均呈现 1890 帧、丢帧 0、音频欠载 0。旧流程 BUFFERING 21 次、AudioTrack 初始化 21 次；连续队列分别只有初始 1 次、1 次。两组视频解码器均初始化 1 次。每组 21 个源均关闭，退出残留缓存 0。

这只有 20 个边界，P95 是本次小样本统计，不能推广为所有设备的性能保证。它验证实际 Android 播放管线，但没有测量眼镜物理面板、可听输出或不同 CDN 网络。[正式对照摘要](validation/0.11.0/frames-clean-audio-summary.json)。

### 正常音频 backend 的原始整集验证

未裁剪、未重编码的三份原始 HEVC/AAC 剧集，从头到尾约 205 秒连续播放，没有跳到片尾缩短测试。6169 帧全部呈现，丢帧 0、音频欠载 0，两次帧间隙 33.3ms / 50.0ms；仅初始一次 BUFFERING，源 3/3 释放，退出缓存 0。实际 PCM 缓冲仍为默认 44100 字节（44.1kHz、双声道、16bit，250ms），未强制异步解码。

本组应用 PSS 采样约 98–106MiB，宿主模拟器约 3.6GiB 是整个虚拟机，不能当作应用内存。原始整集只有两个边界，不据此推导普遍 P95；20 边界对照另列。可审查摘要：[原始整集](validation/0.11.0/frames-queue-full-summary.json)。

### 早期关闭音频支持的三秒片段对照（保留诊断证据）

由真实素材重编码得到 HEVC/AAC 测试片段，每段 90 帧。基线视频帧间隙中位数 118.5ms，样本 P95 135.0ms，最大 155.8ms；连续队列为 33.3ms、50.0ms、50.0ms。30fps 的正常帧间隔约 33.3ms。

基线共 21 次进入 BUFFERING，连续队列只有首次 1 次。两组均呈现 1890 帧、丢帧 0，释放 21 个源后残留缓存 0。

**这组音频测量受测试环境影响：**本组队列记录 6 次 AudioTrack 欠载，基线 0 次。随后发现启动参数 `-no-audio` 禁用了虚拟设备音频支持，AudioFlinger 输出延迟约 779ms、活动轨延迟约 1028ms；去掉该参数且保持静音后，原生产配置的 20 次切集恢复为 0 欠载、0 丢帧。因此这组只保留诊断价值，不作为正式音画质量对照。欠载事件出现在相应切集事件之前约 560–600ms，不能把回调中的“距上次投喂时间”当作实际静音长度，也不能仅凭模拟器环境认定无害。

增加 PCM 最小缓冲至 500ms（13 次欠载）和强制异步 MediaCodec（11 次欠载）的试验没有解决异常，均未进入生产代码。恢复音频 backend 后不需要这些改动。原始完整三集在旧环境中也出现过 1 次欠载，证据同样保留。

### 非法裁剪边界样本

初次 stream-copy 裁剪片段声明时长 3.133333 秒，但最后视频包结束在 3.266666–3.333333 秒。该组 20 次切集队列记录 17 帧丢弃，基线 0；记录保留，不拿该组代替合法时间戳素材验收。这也说明异常媒体时间线仍可能影响连续队列边界。

### 正式主页面状态与释放

五项 Android 场景通过：三集自动连播、播完一集定时停止后手动下一集、手动跳集不消耗结束计数、从头重播重新计数、播放中关闭预加载。验证了同一播放器、集数与标题同步、完成记录、保持亮屏和退出缓存清理。

眼镜分支 JVM 核心 229 项、Android/Robolectric 单元 43 项通过；TV 分支分别为 221 项、17 项，失败均为 0。两分支的 Android instrumentation APK 也编译通过。覆盖完整缓存原子接管、预算与 pin、失效文件禁止网络回退、源/period 所有权以及旧回调不能误释放新资源。

## 使用与限制

开启设置中的预加载及自动连播即可使用；无需另设队列参数。网络不足、下一集未完整缓存时仍可能等待。当前结果不代表不同编码、实际 CDN、电视硬件、眼镜光学画面或可听音频均已达到零间隙。已有的预加载关闭选项仍可随时回退到普通切集。

三种发行变体沿用原签名，TV 名称为红果TV；眼镜 Keyboard 保留内置输入法但不含语音，Full 保留内置输入法及离线语音。

发布构建沿用现有 lintVital 跳过参数；没有把 lintVital 计作通过的检查。版本号 TV 为 0.11.0-local / code20，Keyboard 与 Full 分别为 0.11.0-rayneo-keyboard、0.11.0-rayneo-full / code26。
