# Approved maintenance ports, 2026-11-10

These changes are adapted independently to X3Pro and TV. The minimum Android versions remain API26 and API21 respectively. Package/signing identity and playback request signing/budgets are unchanged.

Implementation order:

1. Known cover CDN compatibility, including old cache/download/decode failures.
2. Stable per-episode completion history, persistence, backup and selection indicators.
3. Focusable login QR enlargement, shared refresh and lifecycle cleanup.
4. Owner-partitioned deletion/favorite intent, signed favorite writes and conservative read-back confirmation.

Only the listed capabilities are adopted. Upstream login requirements, identity rotation changes, guest-history uploads and unrelated UI/account stack changes are excluded.

Deletion is local intent, not a cloud history delete. A list without established completeness cannot confirm cloud removal merely by absence. Guest history/favorites are never bulk uploaded. Account partitions survive logout and remain isolated; explicit rewatch/re-favorite replaces the corresponding intent.

Signed-in deletion/favorite operations wait until account intent state has loaded; an operation shown as not ready leaves local state unchanged rather than retaining a potentially lost Activity-only request. Playback remains available with local checkpoints. Ambiguous favorite submissions are not silently repeated; the account page exposes their status and an explicit retry.

Implementation, independent review and the final serial TV/Keyboard/Full regression matrix are complete. Targeted logs and final reports are recorded under `outputs/review-2026-11-10/implementation` in the enclosing workspace. No new release, push or device installation is part of this implementation request.

Cover compatibility passed independent review and a fresh scoped test run: TV 13 core / 18 app tests; X3Pro 13 core / 17 app tests, with no failures, errors or skips. The tests cover malformed/unsupported URLs, HTTP/decode failures, cache repair/reuse, real HTTP redirects and cancellation during decode. One public compatibility-CDN sample returned a JPEG (recorded in `cover-cdn-probe.json`); this is not a guarantee for every upstream image.

Episode completion passed independent review and a fresh scoped run in both products (26 core / 6 app tests, zero failures/errors/skips), plus the implementer's 54 core / 17 app regression run. Exact episode IDs, retention limits, restart/delete/clear, old/new backups and Android JSON type validation are covered. The actual EpisodePanel fixture verifies focus/current/completed presentation; detail-grid coverage is helper/source-level, not a full-Activity fixture.

QR enlargement passed independent review and a fresh scoped run in both products (10 core / 13 app tests, zero failures/errors/skips). New fixtures run on API21 TV / API26 X3Pro and cover presentation-only enlargement, shared refresh, interrupted/late requests, independent expiry, corrupted saved authentication, accepted login cleanup, focus and constrained scrollable measurement. No real account login or physical-device result is claimed.

The account protocol/context slice passed independent review and 33 core tests per product. Tests establish captured owner/epoch checks, strict success and raw membership parsing, signed request-byte/header consistency, and real HTTP-loopback rejection of transparent POST retries/redirects. Application review and fixtures cover immediate deletion suppression, per-account isolation, blocked requests, durable intent retirement, partial read-back, explicit retries, stale list/selection rejection and local-only teardown. Eight focused MainActivity fixtures establish helper/checkpoint wiring, not a full onCreate/playback lifecycle. This is fixture evidence, not a live-account mutation result.
